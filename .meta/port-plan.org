#+title: Porting context surfaces from the source project to a Rails shop
#+date: 2026-11-23

* Why
The owner decided (2026-11-23) to repurpose agentic-rails as the Rails home for what the source project built:
- telemetry as the first priority;
- worktree slots;
- named runners;
- a log check that exits non-zero;
- dev-only endpoints and WebMCP tools;
- e2e and property-based browser testing.

The calculator was a vehicle. A pet shop (products, cart, checkout) is a better one: it has a genuinely
consequential action (checkout) next to undoable ones (cart).

The source of truth for the pattern is the source project's =contract/surfaces.org= and =AGENTS.md= ("A subagent run,
in order"). Its .meta notes explain why each rule exists: webmcp-tools, webmcp-evals, games-research,
subagent-process.

* State of this repo (checked 2026-11-23)
- Rails 7.2, Ruby 3.3.8 (Gemfile), Postgres 15 and Redis via docker-compose, Turbo, rspec and capybara.
- The app: a =Product= model and a health controller. No cart, no checkout.
- The last commit was 2025-09-23 (an EDD guide). =worktrees/= exists.
- *Toolchain gap:* only system Ruby 2.6.10 is installed. There's no Ruby 3.3 under asdf, mise or rbenv. Either
  install it (=asdf install ruby 3.3.8=) or run everything in Docker. The owner decides.
- *Port clash:* compose hard-codes =3000:3000= and =5432:5432=. That is the problem the source project's slots solved,
  so ports must come from a slot.

* What carries over, in order
1. *Slots.* =bin/slot claim|up|info|down|release=, or a rake equivalent:
   - port 4900+n (4900 is main, the owner's), with SQLite per slot: =XDG_STATE_HOME= points the slot at its own
     state dir, so =config/database.yml= puts the database there unchanged;
   - a per-slot state dir under =$XDG_STATE_HOME/agentic-rails-slots/slot-n=;
   - a frozen checkout per commit, =worktrees/slot-n-<task>=, which the owner wants named for both signals. The
     server runs from it, so =/.well-known/appspecific/com.chrome.devtools.json= (already on main, from
     =Rails.root.realpath=) names that worktree, and DevTools > Sources > Workspace on =:490n= maps to it with
     no per-slot code;
   - =info= gives machine-readable output (=--json=), because awk parsing was a friction point;
   - =up= prints its own "restarting <port> for <sha>" line, because agents announced shas from memory, wrongly,
     three times.
2. *Runner identity.* W3C =traceparent= and =baggage= carrying =app.driver=, =app.run=, =gen_ai.agent.name=
   and =gen_ai.agent.id=; =?ff=driver:…,run:…= on page URLs; =window.appRunner= for Playwright. =human= only after
   real input; =unknown= until then; =automation= for an unnamed webdriver. A separate =app.trigger=
   (input/timer) for lines nobody typed.
3. *The logs, joined on one trace id:*
   - the access log;
   - spans in OTLP-shaped JSONL (opentelemetry-ruby, written to the slot's state dir);
   - consent-gated browser events (a beacon);
   - a domain record per action (cart and order events), standing in for the source project's stack and memory inspectors.
4. *=bin/report --since N --state DIR=*, the =bb report= equivalent. It exits 1 on any problem, and a window
   with 0 traces is a failure. Problem kinds come first:
   - =:server-error=, =:invalid-span=, =:browser-line-without-span=, =:span-without-record=;
   - =:driver-mismatch=, =:runs-share-session=;
   - domain oracles: cart totals recomputed from the line items, an order total matching its cart,
     "checkout happened once per idempotency key".
5. *Dev-only endpoints:* =GET /api/build= (sha, branch, slot) and a footer; =GET /api/trace/:id= (the records for
   a trace, with no paths); =GET /api/report=; =/.well-known/appspecific/com.chrome.devtools.json=. Outside dev,
   =/api/build= answers 204, so there's no console error. A test asserts it.
6. *WebMCP tools* (Chrome's real API, static registration):
   - =shop_search_products= (read-only);
   - =shop_add_to_cart= / =shop_update_cart= (undoable, =consequentialHint false=);
   - =shop_read_cart= (read-only; returns its trace and the record it read);
   - =shop_checkout= (=consequentialHint true=: the first truly consequential tool);
   - =shop_trace= (dev, =debugging true=);
   - =shop_report= (dev).

   =untrustedContentHint= goes on anything that echoes user or product text. The page's tool fields are read
   through string keys, because advanced builds renamed fields twice in the source project.
7. *Tests and runners:*
   - Playwright with =BASE_URL= plus =BROWSER_STATE= (both required);
   - per-run session names, ended in =afterAll=;
   - an idle reaper for runner sessions;
   - a =probes/= directory outside the checks (a =document.modelContext= recorder);
   - property-based testing with Bombadil against a slot: carts never go negative; adding then removing is the
     identity; totals match the line items; checkout is idempotent;
   - =pipefail= in every wrapper, and each runner with its own output dir;
   - WebMCP evals (=webmcp-evals= smoke mode first: no model, no key).
8. *Process:* AGENTS.md with "A subagent run, in order" and "Before a branch or PR leaves draft":
   - an early draft PR, pushed every 30 min;
   - =/code-review= at medium; clean means 0 Important, nits listed, never blocking;
   - the agent makes its own ready claim, with "## Testing done";
   - the coordinator re-checks the claim from the logs;
   - merge commits only, followed by a post-merge e2e routine;
   - REVIEW.md imported into CLAUDE.md.

* First steps, each a subagent run under that loop
1. The toolchain decision, then =make check= green as the repo stands today.
2. Slots, ports and the dev footer (=/api/build=): the same shape as the source project's slots.
3. Runner identity, the spans file, and =bin/report= with 0 problems over a non-empty window.
4. The shop: products, cart, then checkout, each with its domain record and a report oracle.
5. The WebMCP tools, then the evals and the Bombadil properties.

* Best guesses (2026-11-24)
The owner asked for best guesses over escalation here: this repo explores where the contract runs out. Each
guess says what would change it.
- *Toolchain:* Ruby 3.3.8 through asdf, settled by step 1. Docker stays out until a container target needs it.
- *Database per slot:* SQLite, one file per slot, isolated by =XDG_STATE_HOME= alone (hub C6). No Postgres, so
  no per-slot naming rule. Revisit if a feature needs concurrent writers SQLite can't serve.
- *Oracle for the service graph:* a sibling lab's span model (declared edges vs edges seen in spans) is a
  reference, not the oracle. The oracles stay in =bin/report=, recomputed from this app's own records (cart
  totals, order vs cart, one checkout per idempotency key). Revisit if a second service appears.
- *Restarting main:* when 4900 is down, restart it in a detached tmux session, rerun a traced probe and renew
  the port registry's pid; done 2026-11-24 23:32 after the session was killed around 11:00.

* Gap: coverage before flags (2026-11-24)
No flag exists here yet. Before the first sorry start, coverage of UI and routes has to be first class: hub
=slot.org= "Gap: coverage is not first class yet", candidates G11-G15. For this repo that means:
- route × flag path coverage from the spans (Rails routes dispatch at run time, so =bin/rails routes= alone
  can't show a flag's reach), plus =Coverage= / SimpleCov on each side's files;
- the registry names each side's files, so removing the legacy path is a deletion the gate can prove
  (nothing else references them; coverage shows them entered only through the dispatch point);
- dead-code detection: none yet; debride (static) and coverband (runtime) are the candidates;
- probes use =?ff= overrides extensively; the full Playwright and Bombadil suites run on defaults only.
